# Island flow for FINN: summary report

FINN accelerators turned into bitstreams by **parallel per-node synthesis, parallel
place-and-route of "islands" of nodes, RapidWright stitching and a short final assembly into a
pre-built shell**, instead of one global Vivado run. Branch `feature/rapidwright-islands`;
detailed log in `NOTES_ISLANDS.md`, raw timing data in `data/`, tables below regenerated by
`summarize_breakdown.py`. Status: 2026-10-07.

## Results at a glance

Wall time from the FINN frontend model (after FIFO sizing) to a bitstream, 100 MHz, each build
alone on a 64-core / 128-thread EPYC 9554P with 755 GB. All builds: 0 routing errors, setup and
hold met.

| board | model | baseline flow | baseline | island flow | speedup |
|---|---|---|---|---|---|
| ZCU104 | TFC | FINN Vivado ZynqBuild | 644 s | 369 s | 1.75x |
| ZCU104 | CNV | FINN Vivado ZynqBuild | 891 s | 436 s | 2.04x |
| ZCU104 | CNV PE=SIMD=1 | FINN Vivado ZynqBuild | 811 s | 425 s | 1.91x |
| ZCU104 | VGG10 | FINN Vivado ZynqBuild | 2112 s | 1434 s | 1.47x |
| ZCU104 | MobileNet (ZCU104 folding) | FINN Vivado ZynqBuild | 5871 s | 5801 s | 1.01x |
| U55C | TFC | global Vivado, same shell | 1528 s | 738 s | 2.07x |
| U55C | VGG10 | global Vivado, same shell | 2980 s | 1697 s | 1.76x |
| U55C | MobileNet (U250 folding, 398k LUT) | global Vivado, same shell | 5424 s | 2713 s | 2.00x |
| U55C | (reference) TFC / VGG10 / MobileNet | Vitis platform flow | 4860 / 7307 / 10756 s | 738 / 1697 / 2713 s | 6.6 / 4.3 / 4.0x |

Fair comparisons use the same shell and the same Vivado settings on both sides: synthesis and
implementation steps/directives of the platform's regular flow (FINN's Zynq strategies on the
ZCU104, Vivado/v++ defaults with phys_opt on the U55C). The island flow's shell is built once per
board / clock / DMA interface (~8 min ZCU104, ~20 min U55C) and cached; the baselines, like
FINN's regular flow, synthesize the shell IPs in every build. The Vitis rows are not like for
like: v++ re-implements the much larger Vitis platform (static region, HBM subsystem) per model;
on the U55C the island flow uses a small Vivado-only shell (XDMA PCIe x16 + on-chip memory, not
XRT-compatible).

## How the two flows work

```
FINN's regular flow (one big serial job)
  HLS/RTL IP per node -> stitched IP per partition -> block design with the shell
  -> synthesis of everything -> opt -> place -> phys_opt -> route -> bitstream
     (one Vivado run, effectively single-machine-thread-bound for long stretches)

Island flow (wide parallel work, short serial tail)
  HLS/RTL IP per node
  -> [parallel]  out-of-context synthesis of every node (up to ~80 Vivado runs at once)
  -> group the node chain into islands; size each island from its synthesized resources and
     place it as a rectangle/staircase over columns that have the LUT/BRAM/DSP/URAM mix it needs
  -> [parallel]  place-and-route of every island inside its pblock (routing contained)
  -> RapidWright: drop the routed islands into the top netlist, route the few nets between them
  -> assembly: shell (pre-built, opened while the islands run) + accelerator -> route the
     boundary and clock -> bitstream
```

Intuition: Vivado's global implementation is mostly serial; its cost grows with the whole design.
The island flow cuts the design along FINN's natural seams (a dataflow chain of nodes with
streaming interfaces) so that the expensive parts run as many small, independent Vivado jobs,
and keeps for the serial tail only what genuinely needs the whole picture.

Techniques exploited:

1. **Node-level out-of-context synthesis in parallel.** Every distinct node is synthesized on
   its own; heavy nodes get their own Vivado run (longest first), small FIFOs / width converters
   share sessions (Vivado's ~30-60 s start/device-load cost is paid once per session).
2. **Resource-aware islands.** The node chain is cut into contiguous islands (balanced by a
   cost from the synthesized LUT/FF/BRAM/DSP/URAM counts). A skyline packer gives each island a
   variable-size staircase region over columns with the right resource mix, at least 30 rows
   per column and >= 60 % of its bounding box filled, searching utilization (0.5..0.85) and
   island count. (A 400k-LUT MobileNet did not fit the old lane-based "snake" at all.)
3. **Parallel island P&R with contained routing.** Each island is a small Vivado job in a
   pblock with CONTAIN_ROUTING, so the islands' implementations do not collide.
4. **RapidWright stitching.** The routed islands are placed into the top-level netlist as-is
   (populateBlackBox) and only the inter-island nets are routed (PartialRouter) - no Vivado
   global run over the accelerator.
5. **A pre-implemented, cached shell.** The DMA/host infrastructure is implemented once with a
   placeholder for the accelerator, then black-boxed with its routing locked. The assembly
   Vivado opens it while the islands are being built (overlapped with the parallel phase).
6. **Same optimizations as the baseline.** Both flows run the same synthesis options and
   opt/place/phys_opt/route steps; the island flow only adds steps it alone needs (a fixed
   kernel-clock root in the U55C shell, see below).

## Where the gains come from (and where not)

Full MobileNet on the U55C, same shell, step by step (seconds):

| | global Vivado | island flow | effect |
|---|---|---|---|
| FINN preparation | 585 (HLS + stitched IPs) | 121 (partitions + IODMA HLS) | no stitched-IP / block-design packaging of the accelerator |
| synthesis | 1047 + 32 (all IPs incl. shell, top) | 263 (157 nodes in parallel) | node-level parallelism, shell cached |
| placement | 218 + 1069 + 64 (opt, place, phys_opt) | 54 + 476 (floorplan, 20 islands in parallel) | island-level parallelism |
| routing | 1197 | inside the islands + 248 (stitch) + 1080 (assembly route) | **no gain yet** |
| other | 80 + 1132 (bitstream, reports, checkpoints, link) | 273 + 120 + 75 (read accel, bitstream, reports) | smaller serial overheads |
| **total** | **5424** | **2713** | **2.0x** |

The gain comes from synthesis (~4x), placement (~2.5x) and fixed Vivado overheads; **the final
route at assembly costs about as much as the baseline's whole global route**, although most
nets arrive routed. The same holds on the ZCU104 (VGG10: 319 s assembly route vs 250 s global
route). This serial tail now bounds the speedup at ~2x.

## Known problems and limits

* **Serial assembly route.** Vivado's final route_design over the whole design is the largest
  serial step (MobileNet U55C 1080 s of 2713 s). Next lever: make it touch only the nets that are
  really unrouted (boundary, clock, the few stitch leftovers) instead of re-processing the
  pre-routed accelerator.
* **One huge node dominates synthesis.** The ZCU104 MobileNet has a standalone Thresholding_rtl
  with 1024 channels in LUT ROM: ~50 min to synthesize with the baseline's PerformanceOptimized
  settings (18 s with RuntimeOptimized, which would be unfair to the baseline). Node-level
  parallelism cannot shorten a single node; such nodes would have to be split.
* **Dense designs give few islands.** The ZCU104 MobileNet fits only as one island (the skyline
  packer is enabled for the Alveo region so far), so its P&R is not parallel at all -> 1.01x.
  Fewer, larger islands also make the largest island the critical path (ZCU104 VGG10: 4 islands,
  592 s).
* **Shell boundary effects.** The shell is routed and locked with its own clock tree; adding the
  accelerator's clock loads shifted the skew and a few locked shell paths missed hold by up to
  60 ps. Fixed in the U55C shell by pinning the kernel clock root (USER_CLOCK_ROOT) when the
  shell is built; a repair pass (unlock + re-route the failing nets) remains as a fallback.
* **Pins boxed in by island routing.** Islands keep their internal routing, which can block the
  access to an island's boundary pins; RapidWright then gives up on a few nets (MobileNet: 8)
  and Vivado routes them at assembly. Capped at 10 stitch iterations to avoid wasted time.
* **QoR.** The floorplan constrains the placer (islands at 50-65 % LUT utilization). All builds
  meet timing at 100 MHz; slack is similar to the baselines (MobileNet U55C WNS +0.122 vs
  +0.135 ns), but higher clocks were not studied.
* **Vitis platforms.** On the U55C, a cached shell inside the Xilinx Vitis platform (nested
  partial reconfiguration of its user region) failed on platform-specific DFX rules (the last:
  GND routing at the static/dynamic boundary), so the per-model v++ link stays (~2-2.4 h, no
  speedup). The ~2x above uses a Vivado-only shell that XRT cannot run.
* **Memory bursts.** Peak use is short: ~80 Vivado runs and ~310 GB (sum of per-process peaks)
  during node synthesis; island P&R ~120 GB. A machine with less memory gets fewer parallel
  runs (handled by the Vivado slot limit).
* **Functional coverage.** Island-built kernels were checked against FINN's stitched-IP RTL in
  gate-level simulation (TFC, CNV, VGG10, MobileNet half-PE; identical outputs and cycle counts);
  no FPGA runs yet.
